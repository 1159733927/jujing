# 阶段 1：可复算排盘基础产品

阶段 1 的验收目标不是“页面上有字段”，而是相同输入与同一规则配置在任意部署中得到相同结果，并能解释与外部排盘工具的差异。

## 问真页面对标

2026-08-31 用 Chrome 检查问真八字网页版排盘入口，当前页面提供：姓名、性别、公历/农历/四柱切换、点击式出生时间选择器、出生地址选择、夏令时、真太阳时、早晚子时、保存、开始排盘，以及排盘后的生辰、合盘、流盘、参数和设置视图。出生时间选择器支持 1801-2100 年滚轮选择和 `199303270255` 这类出生年月日时分快捷输入。

我们的产品对齐这个主流程，但事实源不依赖问真，也不在线抓取问真结果。问真只作为人工样例采集与差异报告来源：每个样例录入固定输入、对方输出和采集时间，再由本地测试生成结构化差异。

## 规则配置档案

每个命盘版本必须保存完整输入快照以及以下配置：

- `calendarSystem` / `lunarLeapMonth`：公历、农历及闰月来源输入。
- `timezone` / `dstPolicy`：IANA 时区与历史夏令时处理策略。
- `useTrueSolarTime`：是否按标准经线、出生经度和均时差校正。
- `dayBoundary`：午夜换日或 23:00 子初换日。
- `luckMethod`：起运算法 `sect1` 或 `sect2`。
- 引擎、历法、时间校正和起运规则版本。

默认档案为：IANA 历史时区自动处理 DST、真太阳时开启、午夜换日、`sect1` 起运。所有默认值会被规范化写入快照，不能只依赖运行时代码默认值。

## 问真差异分类

差异报告不能只输出“相同/不同”，至少区分：

1. 输入归一化差异：历法、闰月、地点、经纬度或时区不同。
2. 时间校正差异：DST、真太阳时或标准经线不同。
3. 日界差异：午夜与子初换日规则不同。
4. 节气边界差异：交节时刻或历书版本不同。
5. 起运差异：顺逆行、折算方法或起运流派不同。
6. 数据展示差异：核心四柱相同，仅附属字段命名不同。
7. 未解释差异：进入人工复核，不允许自动改规则追平。

系统落库使用四个可接受分类：`dependency`、`school-rule`、`timezone-location`、
`display-rounding`。每条新接受差异都必须选择分类并填写理由；`bug` 只能进入修复队列，不能接受。
历史记录没有分类时保持可读，重新审核时必须补齐。

当前 API 提供 `POST /v1/bazi/compare`：调用方提交固定出生输入、样例编号、来源和人工记录的期望字段，服务返回机器可读的叶子级逐字段差异，例如 `pillars[0]`。这些 path 可原样用于 `POST /v1/bazi/wenzhen/fixtures` 的 `acceptedDifferences`，避免后台预览和入库校验口径分裂。真实截图先通过 `POST /v1/bazi/wenzhen/evidence` 进入 SHA-256 不可覆盖证据库，再由 fixture 保存稳定 `evidenceRef`。仓库内已核验样例还必须维护脱敏的 `evidence-manifest.json`，离线 v2 差异命令会校验引用、hash、大小、MIME、采集时间、重复和孤儿证据，并读取私有证据目录核对每张截图本体；缺图或文件被替换时直接失败。外部结果必须人工确认来源和采集时间；不得把尚未核验的本地结果标记为问真结果。

地点选择写入命盘快照时同时保存 `placeCode` 与 `geoDataVersion`。经纬度、时区和地点名称仍保存为不可变快照，因此即使行政区划数据后来升级，旧命盘也能按原值复算。

全国地点分成两套事实：`province-city-china@8.5.8` 只提供行政层级，`/v1/birthplaces/administrative` 可搜索这些区县；坐标是另一套有来源和版本的数据。没有坐标证据的地点会显示但不可用于排盘，绝不能用 `(0,0)`、城市默认值或相邻区县坐标代替。

问真是外部参照，不是不可质疑的事实源。对照样例必须保存采集日期、输入、对方输出截图/人工抄录、我们的规则版本和复核状态。
差异报告的通过状态仅覆盖 fixture 实际填写的 `expected` 字段。manifest 按四柱、时间校正、专业表、
`GET /v1/bazi/wenzhen/diff` 与离线 `pnpm wenzhen:diff` 都会汇总断言覆盖率；当前 6 条真实样例的计数为 `6/5/5/1/1`，并已在用户端命盘页和专家后台展示。该计数不能据此宣称完整功能一致；完整验收以 `pnpm wenzhen:gate` 返回 0 为准。

## 数据与删除

- `chart_versions` 永远追加，不原地覆盖；报告绑定确切 `chart_version_id`。
- 软删除只隐藏 profile，不能删除历史版本或使既有报告失去引用。
- 恢复时若已有活动命盘必须返回冲突，不隐式覆盖。
- 硬删除属于后续账户与隐私生命周期工作，执行前必须检查报告引用和保留政策。

## 发布门槛

- 全仓类型检查、单元测试与生产构建通过。
- 所有外部对照 fixture 标明来源与验证状态；未验证样例不能宣传为“与问真一致”。
- PDF/PNG 经真实渲染检查，无裁切、字体缺失或隐私字段遗漏。
- 地理数据库对数据版本、覆盖数量、缺失坐标和来源许可提供机器可读报告。
