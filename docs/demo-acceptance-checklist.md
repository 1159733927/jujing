# 投资人 Demo 验收清单

这份清单只验证“本地可真实演示”的最小闭环，不等同于生产发布验收。

## 1. 启动演示环境

```sh
pnpm install
pnpm dev:demo
```

预期结果：

- 用户端可打开 `http://127.0.0.1:4173/`。
- 命盘页可打开 `http://127.0.0.1:4173/chart`。
- 报告历史页可打开 `http://127.0.0.1:4173/reports`。
- 专家后台可打开 `http://127.0.0.1:4174/admin/`。
- API 健康检查为 ready。

## 2. 不花模型费用的本地验收

另开终端运行：

```sh
pnpm smoke:demo
pnpm test
pnpm typecheck
pnpm build
pnpm wenzhen:diff
```

预期结果：

- `pnpm smoke:demo` 通过 API、用户端、命盘页、报告页和后台页面检查。
- 如果当前 shell 没有显式设置后台管理员令牌，Demo 知识库写入检查会显示跳过；这是正常的，不代表页面或 API 不可用。
- `pnpm test`、`pnpm typecheck`、`pnpm build` 全部退出码为 0。
- `pnpm wenzhen:diff` 通过已有问真样例；它只证明当前样例覆盖范围内一致，不代表已经和问真完全一致。
- 账号测试覆盖：admin 可下发 C 端账号；无公开注册；用户可登录、读取会话和退出；禁用账号会撤销现有会话并禁止继续登录；admin 前端可创建、停用和重置密码。
- 后端命盘档案测试覆盖：同一账号主体可创建多个带 `label`/`relationship` 的命盘档案；`GET /v1/charts` 返回全部未删除档案；旧 `GET /v1/charts/current` 返回最近更新档案；第 11 个未删除档案返回 `409`；软删除后可新增档案；恢复会重新检查 10 个档案容量。
- 报告测试覆盖：使用既有命盘生成报告时，必须同时提交 `chartProfileId` 和当前 `chartVersionId`；版本变化返回 `409`；成功报告记录固定保存生成时的命盘档案 ID 与命盘版本 ID。`GET /v1/reports` 默认只列出未归档报告，`GET /v1/reports?archived=true` 只列出回收站报告；`DELETE /v1/reports/:id` 只能归档 `completed` 或 `failed` 报告，并撤销分享、关闭 PDF；`POST /v1/reports/:id/restore` 可恢复自己的归档报告，但不会恢复旧分享 token。`POST /v1/reports/:id/regenerate` 必须为已完成且证据完整的源报告创建新 ID，写入 `sourceReportId`，复用不可变命盘版本、住宅版本和已保存视觉事实，并重新跑当前知识、规则、Harness 和质检。

## 3. 真实报告链路验收

确认服务端运行环境已经配置真实 DeepSeek key，并且报告 readiness 为 ready 后，再运行：

```sh
RUN_REPORT_E2E=1 pnpm smoke:report
```

成功时脚本会等待报告通过 validator、进入 `completed`，并在后台质量增强达到 `qualityStatus: passed` 后创建 7 天有效的只读分享链接，输出 `/shared-report/:id#access=<token>`。可用 `REPORT_E2E_WEB_ORIGIN` 覆盖默认的 `http://127.0.0.1:4173`；不要把 fragment token 改为 query 参数或持久化到浏览器存储。

恢复验收还应确认：在视觉、规则、Harness 草稿或质量审核完成后中断服务，重启后对应已完成阶段不会再次调用模型；旧 worker 丢失 lease 后不得删除新 worker 仍需使用的上传图片。

真实链路默认允许最多 15 分钟（`REPORT_E2E_TIMEOUT_MS=900000`），以覆盖专业推理、报告生成和独立质量审核。超时时会打印最后处理阶段和实际等待时长。

预期结果：

- 脚本上传一张演示图片。
- API 创建报告任务。
- 任务依次进入图片识别、规则评估、Harness 生成。
- 首版报告通过 validator 后状态为 `completed`，创建者无需等待后台质检即可读取。
- 报告包含照片观察、专家资料引用和确定性规则命中。
- 报告通过当前校验器 `generated-report-validator-v17-spatial-attribution-gate`。
- 报告首句必须直接给出人宅合拍结论，不能用“以下是/本报告将”开场；正文应面向普通 C 端用户说明“是否适合、最大加分项、最大扣分项、怎么放大优点、怎么减少缺点”。
- 报告必须给出 2–4 条低风险、可撤销的具体行动建议，每条都落到“住宅中的具体位置 + 具体动作 + 为什么这么做”；不能只写保持整洁、注意通风、继续确认之类的万能话。
- 报告不得把未证实的空间事实写成结论；例如证据只显示“厨房在南侧”时，不得扩写成“南侧厨房和阳台/南侧采光面/南侧门窗”。
- 初稿必须进入独立后台质量增强；`qualityStatus` 使用 `pending`、`running`、`failed`、`passed` 表示进度。不通过时最多自动修订 1 次（初稿加修订稿最多共 2 版），仍不通过、质量审核服务超时、报错或返回坏格式时，已通过 validator 的首版报告仍保留给创建者读取，但 `qualityStatus` 必须落为 `failed`，且不得创建或继续使用分享链接。审核草稿仅供内部追溯，用户端不展示。
- 报告核心必须回答“命盘与住宅是否合拍”，并逐项绑定命盘事实、住宅事实、交叉规则和结论。
- 报告正文不包含代码块、裸代码、JSON、HTML 或 Markdown 表格。
- 从一份已完成报告触发重新生成时，新报告必须保留源报告的 `chartVersionId`、`residenceVersionId` 和已保存视觉事实；不重新读取原图，不复用旧 citations、规则结果、正文或 provenance。

注意：这一步会调用真实模型，可能产生费用。不要把 DeepSeek key 写入代码或提交到仓库；只放在本机 `.env` 或服务端运行环境。

## 4. 手工演示路径

1. 打开“我的命盘”。
2. 选择公历或农历生日，选择出生时间。
3. 用省/市/区县选择器选择出生地点。
4. 确认真太阳时开关、子初换日和起运配置。
5. 保存命盘，检查四柱、十神、藏干、纳音、空亡、地势、自坐、神煞、大运和流盘区域。
6. 回到“住宅分析”。
7. 上传一张或多张住宅照片。
8. 给每张照片标注空间和镜头朝向。
9. 填写住宅整体朝向和格局说明。
10. 生成报告。
11. 打开“我的报告”，确认报告可回看，可打印或保存 PDF。
12. 归档一份已完成报告，确认它从默认列表消失、出现在回收站列表、分享页失效、PDF 返回未就绪。
13. 恢复这份报告，确认它重新出现在默认列表；如需分享，必须重新创建分享链接。
14. 对一份已完成且含视觉事实的报告执行重新生成，确认页面出现一份新报告，并能在详情中看到它来自旧报告但重新跑了当前知识、规则、Harness 和质检。

## 5. 当前不可夸大的边界

- 这是文化研究和娱乐参考报告，不是医疗、法律、财务或人生决策建议。
- 当前问真对照样例数量有限，不能宣称完全复刻问真。
- 地点坐标库是已审核的部分覆盖，不能宣称全国区县坐标全部完整。
- 视频分析、生产级账号安全能力（找回密码、租户隔离、保留期/硬删除策略）、生产级 RAG 调优和大规模专家评测仍属于后续阶段。
