# 用独立、版本化的规则配置承载八字流派算法

## 状态

已采纳。

## 背景

八字计算中存在需要明确选择的流派参数，例如真太阳时、子初换日、起运法，以及旺衰、格局、神煞所采用的算法和规则集版本。这些选择会改变确定性计算结果，必须能审核、复算并解释某张命盘为何得到当前结果。

专家资产及其发布版本解决的是资料、引用、报告依据和结构化住宅规则的治理问题。它们允许文章、规则和 Skill 使用面向专家的内容结构，但不应成为排盘运行时配置。若把流派算法混进知识库，检索结果、文字修订或资产下线都可能隐式改变计算行为，也无法可靠证明历史命盘使用了哪套可执行参数。

## 决策

建立独立的 `BaziRuleProfile` 聚合：

- 可变配置记录使用 `draft`、`in-review`、`published`、`archived` 生命周期，保存工作副本、修订号和提交审核、审核、归档审计字段。
- 配置内容明确保存时间处理默认值，包括时区、夏令时策略、真太阳时、换日边界与起运算法。
- 旺衰、格局和神煞分别保存 `enabled`、`method` 与 `ruleSetVersion`，禁用与尚未实现必须显式表达，不能交给模型临时判断。
- 发布操作生成不可变的 `PublishedBaziRuleProfileVersion`，包含单调版本号、内容哈希以及提交审核、审核和发布的操作者与时间。
- `contentHash` 对规范化后的完整可执行定义计算，用于检测内容漂移；发布版本一经生成不得就地修改。

专家资产可以解释、引用某套流派规则或为报告提供文化资料，但 `PublishedKnowledgeVersion` 与 `PublishedBaziRuleProfileVersion` 是两个独立版本空间：前者是证据内容，后者是可执行计算配置，彼此不能替代。

命盘版本最终必须固定引用一个确切的规则配置发布版本。规则配置更新时，只影响随后新建或显式重新计算的命盘版本；不得批量覆盖或悄然重写既有 `ChartVersion`。若用户要求采用新规则复算，应生成新的命盘版本并保留旧版本及二者差异。

命盘计算请求只接受发布版本 ID，不能接受客户端提供的任意规则定义。服务端仅允许当前仍处于 `published` 状态且为该配置当前发布版本的 ID 用于新计算；归档或旧发布版本仍可被历史命盘读取，但不能用于创建新命盘。规则中的时间默认值只补齐请求未提供的参数，不覆盖用户显式选择。

每个采用专家规则的新 `ChartVersion` 保存 `profileId`、`versionId`、版本号、名称、键和内容哈希组成的不可变引用。PostgreSQL 同时保存发布版本外键和引用快照，JSON 模式保存相同快照。规则升级或归档不会改写旧命盘；选择新版本复算会追加新的命盘版本。兼容期内，未选择发布规则的旧调用仍使用引擎内置规则，并在界面明确显示“未绑定专家发布版本”。

## 结果

这样可以同时满足流派演进、专家审核、结果复现和历史审计。代价是发布配置、命盘版本和报告引用之间需要保持额外的一致性约束；仍使用内置规则且没有发布版本引用的历史数据，不能宣称已由专家规则配置驱动。
